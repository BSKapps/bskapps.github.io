A QLab show prep checklist

5 July 2026

Every QLab operator has a version of this list in their head. Writing it down means the 11pm load-in version of you doesn't have to remember it. This is the sequence for going from "a folder of files the client sent" to a workspace you'd happily hand to another operator, in the order that avoids redoing work.

1. Chase the files early, expect them late

Ask for every asset days before you need it, and ask for the source version - the DAW export, not the phone recording of it. You won't get everything, but whatever arrives early can be fully prepped, leaving show morning for the stragglers only.

2. Convert everything to one format first

Before anything goes in the workspace: one format, one sample rate. WAV at the rig's rate (usually 48 kHz) is the standard answer, and it's the step that prevents the whole class of compressed-file surprises - wrong durations, off-target seeks, silent lead-ins. The reasoning and the traps are in Audio file formats for QLab. Converting first also means every later step works on final files, so nothing has to be redone after a swap.

3. Check channel counts and routing

Find the mono files and the fake-stereo files before the output patch does. Decide the mono strategy once - which channels, what width - and apply it everywhere. The mono traps are covered in QLab workspace habits.

4. Level the workspace to a target

Get every cue to the same perceived loudness so the desk rides one fader, not sixty. Peak-normalised files are not level-matched files - use a LUFS target, then push stings and impacts up deliberately from that baseline. Full method in Setting consistent QLab levels with LUFS.

5. Trim the dead air

Client files arrive with silence padding both ends. A second of lead-in silence is a second of the presenter standing in dead air after the Go. Trim heads and tails, or set start and end markers, on every cue that fires on a specific moment.

6. Number cues so a stranger could follow

Renumber on tens so there's room to insert. Name cues for what they are on stage ("Walk-up - J Smith"), not the filename. The test: could a cover operator run this workspace cold?

7. Set fades, continues, and panic times deliberately

Every fade-out should have a duration someone chose. Auto-continues should exist only where a sequence genuinely wants them. Set the panic (Escape) fade time to something that sounds like a choice rather than a cut. Defaults are for rehearsal; a show file has no accidental settings.

8. Test on the show system, at level

The workspace that works on your laptop with headphones has proven nothing about the show Mac and the rig. Run every cue through the real output patch at something near show level, and listen to the first and last seconds of each - that's where the problems live.

9. Back it up like you mean it

Workspace plus media, bundled, on a drive that isn't the show machine - QLab's "Bundle Workspace" exists for exactly this. Do it again after any late change. The show that loses a machine at 5pm is only saved by the bundle you made at 4.
