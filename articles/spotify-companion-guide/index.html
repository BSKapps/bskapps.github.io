How to control Spotify from Bitfocus Companion

14 June 2026

If you run a Stream Deck through Bitfocus Companion, you can drive Spotify from it: start a track, pause cleanly, fade the volume, jump to a cue point, and show what is playing on the keys. BSK Spotify for Companion is a free, open-source module that does this through the Spotify Web API. This is a quick overview; the module's page has the full step-by-step setup.

What it does

  • Transport control: play, pause, next, previous.
  • Volume control with smooth fades, not just a jump.
  • Cue-point playback: start a track from a set timestamp, and named bookmarks to jump to.
  • Playlist control.
  • Album art on the buttons, including 2x2 and 3x3 art grids.
  • 99 ready-made presets, so most buttons are drag-and-drop.
  • 30 dynamic variables for track name, artist, timing and playback state, to build now-playing displays.

What you need

Bitfocus Companion 4.x, a Spotify Premium account, and a free Spotify Developer app (one per Companion install) for the sign-in. You do not need a paid developer subscription; your normal Spotify account is fine.

Setting it up

In short:

  1. Download the module's .tgz from the latest release (do not extract it).
  2. In Companion, open Modules and use Import module package to load the .tgz.
  3. Open Connections, add a new connection, and search for BSK Spotify.
  4. Paste in your Spotify app's Client ID and Client Secret, then click Authenticate and sign in.

The full walkthrough, including how to create the Spotify Developer app and the exact redirect URI to use, is on the module page.

Using it on the buttons

Drop the ready-made presets onto your Stream Deck pages for instant transport, volume and playlist buttons, then swap in the variables to show the current track and time. Build a cue point or bookmark button when you need a song to start from an exact moment in a show.

If the connection drops mid-show

On macOS the module has an offline fallback: if the Web API drops out, the transport buttons keep working through the local Spotify app, and it recovers automatically when the API comes back. That safety net is the reason it is worth running over a generic web request.

It is free and MIT licensed, with the source on GitHub.
