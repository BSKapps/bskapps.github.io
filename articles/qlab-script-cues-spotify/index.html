QLab script cues for Spotify control

9 May 2026 · Updated 3 October 2026

You can drive Spotify from QLab with a Script cue. Pre-show music, walk-in playlists, post-show cover beds, between-band changeovers: a few lines of AppleScript keep the operator on one Go button instead of switching apps mid-show.

License note. Script cues require a licensed copy of QLab. Everything below assumes you have one.

The shape of a Spotify Script cue

A Script cue in QLab takes AppleScript directly. The Spotify app on macOS has its own scripting dictionary, so you address it by name and send commands. Every example below goes into the script field of a single Script cue.

tell application "Spotify"
    play
end tell

That is the simplest version. It resumes whatever was last playing. The useful cues are the ones that target a specific track or fade in cleanly.

Play a specific track

Spotify's AppleScript dictionary accepts URIs in the form spotify:track:<id>. To get a URI on a Mac, right-click a track in Spotify, choose Share, then hold Option and choose Copy Spotify URI.

tell application "Spotify"
    play track "spotify:track:4iV5W9uYEdYUVa79Axb7Rh"
end tell

This is the workhorse for cued tracks. Walk-out song after the bows, sting between scenes, a specific recording for a tribute. Each cue is one line plus the wrapper.

What AppleScript cannot do cleanly

  • Timestamp cueing. AppleScript can set player position, but Spotify always plays from position 0 for a moment before the seek takes effect. The room hears the first half second of the track every time. Volume mute workarounds exist but the result is not clean enough for live use.
  • Playlists from a chosen track. play track "spotify:playlist:..." starts a playlist from its first track. AppleScript cannot start it at a chosen track number, and a start time gets the same moment from position 0 as above.

The BSK Spotify Companion module uses the Web API, which takes a start position for a single track and a start track for a playlist. On playlist plays Spotify ignores the start position, so a playlist always starts from the top of the chosen track. If your show needs either, drive Spotify from Companion instead of AppleScript, and trigger the Companion buttons from QLab if you want a single Go.

Fade volume in or out

Spotify exposes sound volume as a 0 to 100 integer and has no fade command. QLab cannot fade Spotify, so the script ramps Spotify's own volume in a short loop.

tell application "Spotify"
    set sound volume to 0
    play
    set targetVol to 80
    set fadeSteps to 40
    set fadeDuration to 4
    repeat with i from 1 to fadeSteps
        set sound volume to (targetVol * i / fadeSteps) as integer
        delay (fadeDuration / fadeSteps)
    end repeat
end tell

Four seconds, 40 steps, every 100 ms. Smooth enough that the room will not hear the staircase. Reverse the maths for a fade out: ramp from the current volume down to 0, call pause, then set the volume back to where it started, or the next play cue starts silent.

Pause cleanly on a Stop cue

Pair every Spotify play cue with a way to stop it. Easy as a Script cue at the end of a group:

tell application "Spotify"
    pause
end tell

If the SM hits panic and your panic fade is set to a sensible 3 or 4 seconds, your QLab audio cues will fade gracefully. Spotify will not, because it is not part of QLab's audio engine. A Stop cue with the pause script wired to the same group lets you treat Spotify like another device that responds to the show's stop logic.

What to watch out for

  • Spotify must be running and signed in. AppleScript launches it if needed, but the first cue may take a second longer while it boots.
  • Play one track by hand before the show to wake Spotify and confirm it plays on this Mac, not on a Spotify Connect device elsewhere, then leave it.
  • URIs change if a track is re-released. If a cue suddenly misses, copy a fresh URI from Spotify rather than assuming the AppleScript is broken.
  • The fade moves Spotify's own volume slider, not the Mac output or your interface.
