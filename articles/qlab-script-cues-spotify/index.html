QLab script cues for Spotify control

9 May 2026

Spotify is not a traditional show source, but it shows up all the time. Pre-show music, walk-in playlists, post-show cover beds, between-band changeovers. If you are running QLab anyway, you can drive Spotify from cues using AppleScript inside a Script cue, which keeps the operator on one Go button instead of switching apps mid-show.

License note. Script cues require a licensed copy of QLab. Everything below assumes you have one.

The shape of a Spotify Script cue

A Script cue in QLab takes AppleScript directly. The Spotify app on macOS has its own scripting dictionary, so you address it by name and send commands. Every example below goes into the script field of a single Script cue.

tell application "Spotify"
    play
end tell

That is the simplest version. It resumes whatever was last playing. The interesting cues are the ones that target a specific track, fade in cleanly, or recover a known starting point on demand.

Play a specific track

Spotify's AppleScript dictionary accepts URIs in the form spotify:track:<id>. To get a URI, right-click a track in Spotify, choose Share, then Copy Spotify URI.

tell application "Spotify"
    play track "spotify:track:4iV5W9uYEdYUVa79Axb7Rh"
end tell

This is the workhorse for cued tracks. Walk-out song after the bows, sting between scenes, a specific recording for a tribute. Each cue is one line plus the wrapper.

What AppleScript cannot do cleanly

Two things you might expect to work but do not, both because of how Spotify treats AppleScript versus the Web API:

  • Timestamp cueing. AppleScript can set player position, but Spotify always plays from position 0 for a moment before the seek takes effect. The room hears the first half second of the track every time. Volume mute workarounds exist but the result is not clean enough for live use.
  • Playlist playback. play track "spotify:playlist:..." looks like it should work, but AppleScript does not load the playlist as a playback context. You cannot reliably start a playlist via AppleScript.

Both of these are exactly why the BSK Spotify Companion module exists. It uses the Web API directly, which supports both a position parameter on the play call and proper playlist context loading. The Timestamp Cue and Play Playlist presets handle these cleanly. If your show needs either, drive Spotify from Companion instead of AppleScript, and trigger the Companion buttons from QLab if you want a unified Go.

Fade volume in or out

Spotify exposes sound volume as a 0 to 100 integer. There is no native fade command, so you do it with a short loop that ramps the value over time. This pattern is what would otherwise need an audio cue with a volume envelope, except here the audio is coming from Spotify directly.

tell application "Spotify"
    set sound volume to 0
    play
    set targetVol to 80
    set fadeSteps to 40
    set fadeDuration to 4
    repeat with i from 1 to fadeSteps
        set sound volume to (targetVol * i / fadeSteps) as integer
        delay (fadeDuration / fadeSteps)
    end repeat
end tell

Four seconds, 40 steps, every 100 ms. Smooth enough that the room will not hear the staircase. Reverse the maths for a fade out: start at the current volume, ramp down to 0, then call pause at the end so the next track does not start silently.

Pause cleanly on a Stop cue

Pair every Spotify play cue with a way to stop it. Easy as a Script cue at the end of a group:

tell application "Spotify"
    pause
end tell

If the SM hits panic and your panic fade is set to a sensible 3 or 4 seconds, your QLab audio cues will fade gracefully. Spotify will not, because it is not part of QLab's audio engine. A Stop cue with the pause script wired to the same group lets you treat Spotify like another device that responds to the show's stop logic.

What to watch out for

  • Spotify must be running and signed in. AppleScript launches it if needed, but the first cue may take a second longer while it boots.
  • An active playback device matters. Spotify will refuse play commands if there is no active output. The simplest fix is to play one track manually before the show to wake the device, then leave it.
  • URIs change if a track is re-released. If a cue suddenly misses, copy a fresh URI from Spotify rather than assuming the AppleScript is broken.
  • Volume fades touch the system Spotify volume, not your audio interface. If Spotify is going through a Loopback or BlackHole route, sanity check that nothing else gets muted by the same fade.

Script cues will not replace a properly designed audio cue list, but they make Spotify behave like a real source instead of a separate app the operator has to remember to drive.
