Dante network readiness on a Mac

15 April 2026

Dante is usually reliable. When it isn't, it's almost always the network underneath, not Dante itself. Macs are fine Dante endpoints, but a few defaults need attention before you plug into a show. Treat this as a short pre-show checklist.

Use a USB Ethernet adapter with the right chipset

Modern MacBooks have no built-in Ethernet, so you're always using an adapter. Not all adapters are equal, and on macOS the difference is mostly about which USB class the adapter speaks.

Stick to USB-C / Thunderbolt adapters that macOS handles natively (CDC-NCM class). Avoid older ASIX chipsets that need a kernel extension - they tend to drop packets under sustained audio load.

What works reliably on macOS for Dante:

  • Realtek RTL8156 / RTL8156B - 2.5 GbE, CDC-NCM, driverless on macOS 12+. The current safe choice for USB-C adapters. Most UGREEN, Anker, and CalDigit adapters at this price point use this chip.
  • Apple USB-C to Gigabit Ethernet - driverless, deterministic, no surprises.
  • Thunderbolt 3 to Thunderbolt 2 adapter chained with a Thunderbolt 2 to Gigabit Ethernet adapter - goes through the Thunderbolt bus entirely, bypasses USB, and behaves very cleanly on macOS. More cable to manage but a solid option if you already have the adapters from an older rig.

The older RTL8153 is best avoided for Dante work - Audinate's own guidance flags packet loss issues with that chipset. If you have one already and it's been reliable for you, keep it, but the 8156 is the better buy today.

What to avoid: older ASIX parts (AX88772 and similar) that use a vendor-specific protocol and require a kernel extension, any adapter that insists on its own driver download, and random unbranded dongles whose chipset isn't listed anywhere on the packaging.

Confirm the negotiation is clean once plugged in. System Settings, Network, pick the adapter, Details, Hardware. You want Speed: 1 Gbit/s or 2.5 Gbit/s, Duplex: full-duplex, MTU: Standard (1500) for Dante audio. Anything else, fix it before you trust it. (If you're running Dante Video or other multicast-heavy traffic on the same network, that side may want jumbo frames - separate decision, separate setting.)

Turn Wi-Fi off, not just disconnected

Dante Controller explicitly recommends disabling Wi-Fi on the control machine. There's a good reason. If Wi-Fi is on and the Dante network has no internet path, macOS may send Dante Controller's discovery traffic out the wrong interface, or randomly prefer Wi-Fi for mDNS. You'll see devices appear and disappear, clock sync go yellow, and patch commands silently fail.

Switch Wi-Fi off from the menu bar for the duration of the show. Not "disconnect from current network". Off. If you need Wi-Fi at the same time (for cue-firing tablets, phones, a wireless mic receiver with a web UI), put it on a genuinely different subnet and set the Service Order in System Settings so Ethernet is first.

Watch out for subnet clashes

The single most common Dante-on-Mac trap: your Wi-Fi and your Dante network both sit on 192.168.1.x. macOS now has two interfaces claiming the same subnet and has to guess which one Dante Controller should talk to. It guesses wrong. You get a nominally working Wi-Fi, a nominally working Ethernet, and a Dante Controller window full of offline devices.

Options, in order of how often they fix it:

  • Turn Wi-Fi off.
  • Put the Dante network on a subnet that definitely doesn't overlap with anything else. 192.168.10.x or 172.16.50.x are popular choices for a reason.
  • Change the Wi-Fi router's LAN subnet at home so it never matches typical show subnets.

Static IP on the Dante subnet

On a dedicated Dante network with no DHCP, set the Mac manually to an unused address in the same subnet as the devices, with no gateway. Vendor-supplied sheets win over improvisation. If you juggle more than one non-DHCP network, named presets are worth their weight - longer piece on that here.

Turn off energy-saving traps

  • Sleep when display is off - Never, on AC.
  • Wake for network access - off.
  • Screen saver waking Wi-Fi back on - disable.
  • Any VPN client with a kill switch or "route all traffic" toggle - off during shows.

Verify before the house opens

Open Dante Controller. Every device present, green, and clocked. Run a ten-second test tone from a source you trust to a destination you trust. Look at the status dots, not just the meters. If anything's orange, it will go red under load.
