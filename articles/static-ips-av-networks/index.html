Running multiple network adapters on a Mac

18 April 2026

A MacBook used in live production rarely has one network connection. Touring rigs, installs, and even small corporate shows often have the same Mac on Wi-Fi, a wired control LAN, and a dedicated audio network at the same time. Each wants its own settings. macOS will happily run all three concurrently, but it will also happily route traffic out the wrong interface if you don't set it up.

Here's a working approach. If you want to understand the routing mechanics behind why these rules exist, there's a companion piece: Part 2 -- how macOS routes traffic across multiple adapters.

Why you end up with multiple adapters

Typical setups that push you past a single interface:

  • Wi-Fi for internet access, remote support, and software updates.
  • One wired Ethernet adapter for a show control LAN: consoles, media servers, lighting, OSC traffic.
  • A second wired adapter, often on a Thunderbolt dock or second USB-C port, for the audio network (Dante, AVB, NDI).

Three networks, three different subnets, three different rulesets. None of which should be talking to each other.

Pick the right addressing per network

Four options, and which is right depends on the network:

  • DHCP - router hands out an address. Default for Wi-Fi, home, office, most venue back-of-house. Leave it alone.
  • DHCP reservation - router is configured to always hand your Mac the same address. Useful when something needs a stable address on a Wi-Fi network.
  • Static IP - Mac is set manually. The only option when the network has no DHCP server, or when the vendor has assigned you an address.
  • Link-local (169.254.x.x) - no DHCP server answers, so the Mac auto-assigns itself an unused address in 169.254.0.0/16. Set Configure IPv4 to "Using DHCP" and leave it. If there's nothing to respond, macOS falls through to link-local on its own after a short delay. This is how most Dante networks actually run day to day: every device falls to link-local, discovery still works, nobody has to configure anything. Don't dismiss it just because it feels like a fallback.

Service order depends on the day

System Settings, Network, three-dots menu, Set Service Order. This is the setting that tells macOS which interface to prefer for things like default route and DNS when more than one is active. The right order is not universal.

Two common configurations:

  • Office or prep day: Wi-Fi on top, so general internet traffic goes out Wi-Fi. Wired networks still work for their own subnets, they just don't try to be the default route. Useful when you need software updates, cloud storage, or remote support while also on a show LAN.
  • Show day: audio network on top, Wi-Fi below or off entirely. For a lot of rigs, the audio interface needs to win any tie-break - discovery, multicast, the lot. Pushing it to the top of the service order keeps macOS from preferring Wi-Fi for traffic that should stay wired.

Having to reorder this by hand every time you switch contexts is where Locations earn their keep. A "Show" Location with audio on top, a "Prep" Location with Wi-Fi on top, and you swap between them instead of dragging rows in System Settings under pressure. Give each adapter only what it needs

Each interface has its own IPv4, DNS, and router settings. A common mistake is filling in all of them on every interface, which then fights with itself.

  • The internet-facing interface gets IP, subnet, router, and DNS. Usually all via DHCP.
  • A control LAN that has no internet access gets IP and subnet only. No router. No DNS.
  • An audio network on link-local gets nothing at all. Leave Configure IPv4 on "Using DHCP" and let macOS fall through to a 169.254.x.x address automatically. No router, no DNS.

If an interface doesn't need a gateway, don't give it one. Two interfaces with gateways will silently fight about which one is the default route and you'll spend an hour on it at the worst possible time. Switching between rigs

All of this is fine when the Mac lives in the one rig. The moment it travels - same laptop, different venue, different networks - each of those interfaces needs a different configuration. macOS makes that slow. System Settings, Network, interface, Details, TCP/IP, switch from DHCP to Manually, enter four fields, switch to DNS, enter more fields, click OK, back out. Ten steps per interface. Three interfaces, thirty steps. Every show day.

macOS has a built-in feature called Locations (Network pane, three-dots menu) that saves the whole set and lets you swap between them. It works, but it's buried and only stores the top-level config.
