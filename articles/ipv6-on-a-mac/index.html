IPv6 on a Mac: what it's doing and when to care

5 July 2026 · Updated 3 October 2026

Leave IPv6 on. It does not touch IPv4 or Dante. Set Configure IPv6 to Link-local only on a network that advertises IPv6 but does not route it.

Open the network details on any Mac and alongside the familiar 192.168.x.x address there's a block of hex starting with fe80::. That's IPv6, it's been on by default for years, and for AV work the practical questions are simple: what is it doing, will it break anything, and is it ever actually useful on a show network?

What's already happening without you

Every active interface on a Mac gives itself a link-local IPv6 address (the fe80:: one) the moment the link comes up - no DHCP, no router, no configuration. It's the IPv6 equivalent of the 169.254.x.x self-assigned IPv4 address, except it isn't a fallback: it always exists, alongside whatever IPv4 is doing.

If the network has an IPv6-capable router, the Mac also picks up a routable address automatically (SLAAC - the router advertises the prefix and the Mac builds its own address; no DHCP server involved). Home internet connections and phone hotspots increasingly provide this, so your Mac is often reaching the internet over IPv6 without you ever choosing it.

macOS runs both stacks side by side and prefers IPv6 when a destination offers both and the IPv6 path works ("Happy Eyeballs" races the two and takes the winner, so a broken IPv6 path doesn't hang you).

Why your AV network doesn't use it

Almost all production gear speaks IPv4 only: Dante devices, consoles, media servers, lighting processors, most control software. Discovery protocols, static addressing habits, subnet planning - the whole AV networking culture is IPv4, and the address scarcity that IPv6 solves isn't a problem a 60-device show LAN has. Nothing about that is changing soon. Plan your show networks in IPv4 and treat IPv6 on those interfaces as inert background noise.

Should you turn it off?

Mostly: leave it alone. IPv6 runs as a separate stack, it doesn't consume IPv4 addresses, it doesn't interfere with IPv4 subnetting or routing, and Dante traffic neither uses nor notices it. The old advice to disable IPv6 on principle dates from an era of buggier implementations; on a modern Mac it buys you nothing on a show LAN.

The exceptions worth knowing:

  • Networks with broken IPv6. A venue network that advertises IPv6 but doesn't actually route it can cause slow first-connections as the Mac tries IPv6 before falling back. Happy Eyeballs hides most of it, but if browsing on venue internet feels oddly sticky, setting IPv6 to Link-local only on that adapter is a legitimate fix.
  • Tightly controlled show networks. Some networks are locked to known protocols only; a security or network policy may ask for IPv6 off. Fine - it costs nothing there either.

How to change IPv6 on a Mac

IPv6 is set per adapter. In System Settings:

  1. Choose Apple menu > System Settings, then click Network.
  2. Click the adapter (Wi-Fi, or the Ethernet service), then click Details.
  3. Click TCP/IP.
  4. Set Configure IPv6 to Automatically (the default), Manually, or Link-local only, then click OK.

System Settings has no Off for IPv6. Link-local only is the closest: the fe80:: address stays, routable IPv6 stops.

Terminal can do the same, plus a full off. Get the exact service name first:

networksetup -listallnetworkservices

Then, using that name in quotes:

networksetup -setv6linklocal "Wi-Fi"
networksetup -setv6automatic "Wi-Fi"
networksetup -setv6off "Wi-Fi"

The first sets Link-local only, the second puts it back to Automatically, and the third turns IPv6 off on that service, which System Settings doesn't offer. Changing settings needs an admin account; if the command refuses, run it again with sudo in front.

Where IPv6 earns its keep on a system

One case where IPv6 helps: because the stacks are independent, an adapter can drop out of IPv4 entirely while staying connected over IPv6. Wi-Fi is the classic case. On show day you may want the wired networks to be the only thing in IPv4. Wi-Fi with IPv4 off still delivers internet (on IPv6-capable connections), AirPlay, and location services, but it adds no IPv4 subnet and no IPv4 default route, so it can't clash with a show subnet. The adapter stays on the internet and stays out of IPv4 routing.

The short version

  • IPv6 is already running on every interface; that's normal and harmless.
  • AV gear is IPv4 - plan show networks in IPv4 and ignore IPv6 there.
  • Don't disable it out of habit; do set Link-local only on networks with broken IPv6.
  • An IPv4-off, IPv6-only adapter keeps internet and AirPlay without touching show-network routing.
