Companion module setup for common AV gear

25 April 2026

This is a practical reference for getting Companion talking to the gear you are most likely to see on a show. Each section covers which module to use, what to configure, the ports involved, and the things that commonly go wrong. Before any of this will work reliably on a Mac with multiple network adapters, it is worth reading the network setup article first - module connection problems are often a routing issue, not a Companion or device issue.

QLab

QLab has a dedicated Companion module that uses QLab's OSC network interface. In QLab, go to Settings, Network, OSC Access, and enable network access. The default listening port is 53000. Set a passcode if you want - the Companion module has a passcode field.

In Companion, add a QLab instance and point it at the machine running QLab (localhost if they are on the same Mac, or the IP address if on separate machines). QLab listens for OSC on UDP port 53000 by default. UDP works fine on a stable LAN; if your version of QLab supports OSC over TCP and the Companion module exposes the option, TCP is worth choosing on a noisier network for guaranteed delivery.

Useful actions: fire a cue by number or name, go (fires the selected cue), stop, panic, toggle pause. The module also supports feedback, so you can show cue state on a Stream Deck button - running, paused, broken. If you are running multiple QLab workspaces, you can add multiple instances of the module targeting each workspace by name.

For more on how QLab itself is organised for shows, the QLab workspace habits article covers the setup side.

REAPER

REAPER has built-in OSC support that Companion can talk to directly via the Generic OSC module, or via the dedicated REAPER module if it is available in your Companion version. In REAPER, go to Preferences, Control Surfaces, and add a new OSC surface. Set it to listen on a port of your choice - 8000 is common. Enable "Allow binding to IP" and set the outgoing port back to Companion if you want feedback on button state.

Actions like transport control (play, stop, record, rewind), track muting, and marker navigation all work over OSC. If you are using REAPER for multitrack live recording, triggering record-arm and record-start from a Stream Deck at the FOH position is a clean way to avoid walking back to the stage machine between takes.

Shure ULXD and Axient Digital

Shure's networked wireless receivers - ULXD4, ULXD4D, ULXD4Q and the Axient Digital AD4 series - support remote control over Ethernet using Shure's proprietary TCP protocol. The dedicated Shure Wireless module handles the connection and exposes actions for muting channels, reading RF and audio levels, setting gain, and monitoring battery status.

Each receiver is a separate module instance. Configure the IP address of the receiver and the channel number. The receivers ship with DHCP on by default - assign them static IPs or DHCP reservations if you want to use them with Companion, otherwise the address changes between sessions. Keep them on the show control LAN rather than the audio network; they only need IP connectivity, not the low-latency characteristics you care about for audio.

Feedback works well on these modules: a Stream Deck button showing mute state per channel gives the RF tech a clear panel view without opening Shure Wireless Workbench. Battery level can feed button colours for a quick visual check pre-show.

Blackmagic ATEM

ATEM switchers have excellent Companion support via the ATEM module. Add an instance pointing at the ATEM's IP - the address is set in ATEM Setup, which you run the first time you plug in. Static IP is the right choice; ATEM does have a DHCP mode but there is no reason to use it in a fixed system.

The module exposes most of what you would do in ATEM Software Control: cut and auto transitions, input selection on program and preview, auxiliary output routing, upstream and downstream keyers, macro execution, and SuperSource layout on supported models. Macros are the most powerful option - program complex multi-step transitions in ATEM Software Control, then trigger them from a single Companion button.

One thing to watch: if you are running ATEM Software Control on the same Mac as Companion, both are connecting to the ATEM simultaneously. ATEMs support multiple simultaneous control connections (the exact number varies by model and firmware), so this is fine in practice, but if you see unexpected state changes it is worth checking whether something else is sending commands to the switcher.

Barco Event Controller (E2, S3, EX series)

Barco's Event Controllers use a TCP-based control protocol. The dedicated Barco module connects to the device's IP and exposes actions for preset recall, layer control, screen destinations, and transitions. The devices default to DHCP but should be given static IPs on the show LAN for reliable Companion connectivity.

The most common use is preset recall - saving full system states in the Barco and firing them from a Stream Deck button rather than reaching into the Event Master software mid-show. If you are running a multi-screen setup with complex layer stacks, storing named presets and recalling them via Companion keeps the operator interface simple and reduces the chance of accidentally editing a live state.

vMix

vMix runs on Windows and exposes both an HTTP and a TCP control API. The Companion vMix module connects over TCP - point it at the IP of the Windows machine running vMix and the module handles the port. Make sure vMix's web controller / TCP API is enabled in vMix's settings.

Actions cover most of what you would do in the vMix interface: cut and fade between inputs, overlay control, recording start/stop, streaming start/stop, virtual set selection, and replay control. Feedback is solid - button states for recording, streaming, and overlay active status all reflect the current vMix state in real time. This makes a Stream Deck panel above an operator's keyboard a cleaner way to manage a live production than tabbing back to the vMix window.

Millumin

Millumin is a macOS media server with OSC control built in. In Millumin's preferences, enable OSC - the default listening port is 5000, and it is configurable in the project settings if you need to change it. Use Companion's Generic OSC module to connect to it.

OSC commands cover layer playback, clip triggering, opacity, position, and composition recall. Millumin's OSC address space is documented in its manual and is worth reading through before building the Companion layout - the address structure for compositions, layers, and clips is hierarchical, and knowing the paths saves time when setting up actions. If you only need to fire named compositions, those addresses are straightforward and a good place to start.

Stage Timer

Stage Timer (stagetimer.app) is a web-based countdown and clock tool for presenters and stage managers. It has a REST API that Companion can talk to via the Generic HTTP module. The API lets you start, stop, and reset timers, load messages, and control which display is visible - all useful for keeping a conference or corporate show moving without the timer operator needing a second screen open.

Authentication is via an API key from your Stage Timer account settings. The Generic HTTP module handles the GET and POST requests. Stage Timer's API documentation lists all available endpoints; the timer control and message endpoints are the ones most worth wiring up to a Stream Deck.

Spotify

The Spotify module connects via the Spotify Web API and requires OAuth authentication and a Spotify Premium account. You register a developer application in Spotify's developer portal, get a client ID and secret, and authorise the connection through Companion's web UI. This sounds involved but is a one-time setup.

Once connected, actions cover playback control, volume, next/previous track, shuffle and repeat, and switching between playback devices. Feedback shows currently playing track and artist on a button. The practical use case is venue background music: an operator running a pre-show playlist from a Stream Deck without touching the computer running the show stack. Keep Spotify on a Spotify Connect device rather than the main show Mac if possible - having Spotify's audio routing coexist with QLab on the same machine is manageable but adds an audio configuration step.

Smaart

Rational Acoustics Smaart exposes a network API, and the BSK Smaart module connects to it over a websocket. Enable the API in Smaart under Options, Preferences, API, note the port (26000 by default), and point the module at the machine's IP and port. No account or licence server is involved. Because control goes over the network, Smaart can run on a separate measurement laptop while Companion drives it from the show position.

Actions cover trace capture, starting and stopping measurements, delay tracking, the signal generator, and the display toggles you would otherwise reach for by hotkey, including target curves and view presets. On Smaart Suite and the Smaart SPL edition, the module also reads live SPL meters - SPL Fast and Slow in Z, A and C weighting, Leq, LAeq, LCeq, Peak, and exposure - and puts them on buttons as variables with Smaart's own threshold colours, so a Stream Deck can show the room's level at a glance. SPL is not exposed over the API on Smaart LE or RT. SPL values need SPL logging running in Smaart, which the module can start and stop from a button.

When a module stays disconnected

If a module connects successfully in testing but drops out during the show, the usual causes are the device losing its IP (DHCP lease expired or the device rebooted), a network switch losing power or being unplugged and reconnected, or the Mac's routing table changing when an adapter comes up or goes down. Most modules will reconnect automatically once the device is reachable again, but it is worth knowing which ones do and testing it before the show. For modules that don't auto-reconnect, a Companion button that restarts the module connection is a useful thing to have on a hidden or secondary page.
