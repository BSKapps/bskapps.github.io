Companion module setup for common AV gear

25 April 2026 · Updated 3 October 2026

How to get Companion talking to the gear you are most likely to see on a show: which module to use, what to set on the device, the ports involved, and what commonly goes wrong. On a Mac with more than one network adapter, read the network setup article first. Many module connection problems are routing problems on the Mac.

QLab

QLab has a dedicated Companion module that talks to QLab's OSC interface. In QLab 5, open Workspace Settings, Network, OSC Access. The workspace listens on port 53000 by default. Every new QLab 5 workspace gets a random four-digit passcode, and the module's own help says QLab 5 needs a passcode to work reliably from Companion, so copy it into the module's OSC Passcode field. Get it right first time: QLab ignores a client that sends a wrong passcode too many times in a row, and the module stops retrying until you save the correct one.

In Companion, add a QLab connection and point it at the machine running QLab (127.0.0.1 if they are on the same Mac, or its IP address if not). Tick Use TCP. The module only provides variables and feedback over TCP.

Useful actions: go, stop, panic, pause and resume, and start or stop a specific cue by number or ID. With TCP on, feedback shows cue state on a Stream Deck button - running, paused, broken. QLab 5 sends module commands to every open workspace, so to control two workspaces separately, give each its own OSC listening port in Workspace Settings, Network and add one Companion connection per port.

For more on how QLab itself is organised for shows, the QLab workspace habits article covers the setup side.

REAPER

REAPER has built-in OSC support, and Companion's REAPER module uses it. In REAPER, open Preferences, Control/OSC/web, and add a device. Set Control surface mode to OSC and Mode to "Configure device IP+local port", then:

  • Device IP - the IP address of the machine running Companion.
  • Device port - the module's Feedback port. REAPER sends state back to Companion here.
  • Local listen port - the module's Target port. REAPER listens for commands here.

In the Companion connection, enter the REAPER machine's IP and the same two ports. The module defaults to 8000 for the Target port and 9000 for Feedback; use those unless something else on either machine already does.

Actions like transport control (play, stop, record, rewind), track muting, and marker navigation all work over OSC. If you are using REAPER for multitrack live recording, triggering record-arm and record-start from a Stream Deck at the FOH position is a clean way to avoid walking back to the stage machine between takes.

Shure ULXD and Axient Digital

Shure's networked wireless receivers - ULXD4, ULXD4D, ULXD4Q and the Axient Digital AD4 series - support remote control over Ethernet using Shure's proprietary TCP protocol. The dedicated Shure Wireless module handles the connection and exposes actions for muting channels, reading RF and audio levels, setting gain, and monitoring battery status.

Each receiver is a separate module instance. Configure the receiver's IP address and model type; you pick the channel in each action and feedback. The receivers ship with DHCP on by default - assign them static IPs or DHCP reservations if you want to use them with Companion, otherwise the address changes between sessions. Keep them on the show control LAN rather than the audio network; they only need IP connectivity, not the low-latency characteristics you care about for audio.

Feedback works well on these modules: a Stream Deck button showing mute state per channel gives the RF tech a clear panel view without opening Shure Wireless Workbench. Battery level can feed button colours for a quick visual check pre-show.

Blackmagic ATEM

ATEM switchers are well covered by Companion's ATEM module. Add an instance pointing at the ATEM's IP - the address is set in ATEM Setup, which you run the first time you plug in. Static IP is the right choice; ATEM does have a DHCP mode but there is no reason to use it in a fixed system.

The module exposes most of what you would do in ATEM Software Control: cut and auto transitions, input selection on program and preview, auxiliary output routing, upstream and downstream keyers, macro execution, and SuperSource layout on supported models. Use macros for multi-step moves: program them in ATEM Software Control, then trigger each one from a single Companion button.

One thing to watch: if you run ATEM Software Control on the same Mac as Companion, both connect to the ATEM at once. ATEMs accept several control connections. If state changes by itself, look for a second controller.

Barco Event Controller (E2, S3, EX series)

Barco's Event Controllers use a TCP-based control protocol. The dedicated Barco module connects to the device's IP and exposes actions for preset recall, layer control, screen destinations, and transitions. E2 Gen 2 units ship with a fixed default IP that is the same on every unit, so on a system with more than one, change all but one before they share a network. Give every processor its own static address on the show LAN.

The most common use is preset recall - saving full system states in the Barco and firing them from a Stream Deck button rather than reaching into the Event Master software mid-show. If you are running a multi-screen setup with complex layer stacks, storing named presets and recalling them via Companion keeps the operator interface simple and reduces the chance of accidentally editing a live state.

vMix

vMix runs on Windows and exposes both an HTTP and a TCP control API. The Companion vMix module connects over TCP - point it at the IP of the Windows machine running vMix and the module handles the port. Make sure vMix's web controller / TCP API is enabled in vMix's settings.

Actions cover most of what you would do in the vMix interface: cut and fade between inputs, overlay control, recording start/stop, streaming start/stop, virtual set selection, and replay control. Feedback is solid - button states for recording, streaming, and overlay active status all reflect the current vMix state in real time. This makes a Stream Deck panel above an operator's keyboard a cleaner way to manage a live production than tabbing back to the vMix window.

Millumin

Millumin is a macOS media server with OSC control built in, and Companion has a dedicated Millumin module. Millumin listens for OSC on port 5000 by default; change it under Interactions, Manage devices, OSC if you need to. Point the module at the Millumin machine's IP and that port.

The module's actions cover launching columns by number or name, playing media on a layer, stopping all columns, and playing, pausing or jumping the timeline to a named segment. For anything it does not cover, Millumin's OSC address space is documented in its manual and is worth reading before you build custom actions - the address structure is hierarchical, and knowing the paths saves time.

Stagetimer

Stagetimer (stagetimer.io) is a web-based countdown and clock for presenters and stage managers, and it has a dedicated Companion module. The API, and so the module, needs a paid Stagetimer plan. In the module, enter the room's ID and an API key: a room key, generated on that room's controller page, or a team key, created in the dashboard, which works for every room your team owns.

Actions cover starting, stopping and resetting timers, adding and subtracting time, showing and hiding messages, flash and blackout - all useful for keeping a conference or corporate show moving without the timer operator needing a second screen open. The module comes with ready-made presets for the common buttons.

Spotify

For Spotify, use our free BSK Spotify module. It connects through the Spotify Web API, so it needs a Spotify Premium account and a free Spotify Developer app for the sign-in. That is a one-time setup, walked through step by step on the module page. It adds cue points, bookmarks, playlists, volume fades, album art on buttons, 99 ready-made presets and 30 variables, and on macOS it falls back to the local Spotify app if the Web API drops out mid-show. The Spotify Companion guide has the overview.

The practical use case is venue background music: an operator running a pre-show playlist from a Stream Deck without touching the computer running the show stack. Play Spotify on the Mac running Companion, so the offline fallback can take over if the Web API drops. If that Mac also runs QLab, route Spotify's audio deliberately so it does not land on the show outputs by accident.

Smaart

Rational Acoustics Smaart exposes a network API, and our free BSK Smaart module connects to it over a websocket. Enable the API in Smaart under Options, Preferences, API, note the port (26000 by default), and point the module at the machine's IP and port. No account or licence server is involved. Because control goes over the network, Smaart can run on a separate measurement laptop while Companion drives it from the show position.

Actions cover trace capture, starting and stopping measurements, delay tracking, the signal generator, and the display toggles you would otherwise reach for by hotkey, including target curves and view presets. On Smaart Suite and the Smaart SPL edition, the module also reads live SPL meters - SPL Fast and Slow in Z, A and C weighting, Leq, LAeq, LCeq, Peak, and exposure - and puts them on buttons as variables with Smaart's own threshold colours, so a Stream Deck can show the room's level at a glance. SPL is not exposed over the API on Smaart LE or RT. SPL values need SPL logging running in Smaart, which the module can start and stop from a button.

When a module stays disconnected

If a module connects successfully in testing but drops out during the show, the usual causes are the device losing its IP (DHCP lease expired or the device rebooted), a network switch losing power or being unplugged and reconnected, or the Mac's routing table changing when an adapter comes up or goes down. Most modules will reconnect automatically once the device is reachable again, but it is worth knowing which ones do and testing it before the show. For modules that don't auto-reconnect, a Companion button that restarts the module connection is a useful thing to have on a hidden or secondary page.
