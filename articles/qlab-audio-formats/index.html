Audio file formats for QLab: what to use and what to avoid

5 July 2026 · Updated 3 October 2026

Use WAV or AIFF at 48 kHz, and convert everything else before it goes in the workspace. QLab will play almost anything macOS can decode - WAV, AIFF, CAF, MP3, AAC and more - but "it plays" and "it plays predictably every single time" are different standards. The files a client emails you were made for convenience, not playback.

The safe choice: uncompressed, at the show's sample rate

For anything that matters, use WAV or AIFF. QLab's own documentation recommends AIFF, WAV and CAF most highly.

  • No decoding surprises. Uncompressed PCM has nothing to unpack - seeking is sample-accurate, durations are exact, and the CPU cost is trivial.
  • 48 kHz is the usual show standard, matching video and most playback systems. Standardise every file on it and run the interface at the same rate, so every machine plays the workspace the same way. QLab converts other rates on the fly, and Figure 53 call that conversion very efficient, so mixed rates will not strain the Mac. They do advise against rates above 48 kHz unless other gear in the system needs them.
  • 16-bit or 24-bit. Use 24-bit if the source has it. 16-bit is fine for playback.

Disk space stopped being an argument years ago. A three-hour show's worth of stereo WAVs is a few gigabytes on a machine with hundreds free.

MP3 and AAC: fine until they aren't

Compressed files mostly work, and for a walk-in playlist nobody will hear the difference. Timing is another matter:

  • VBR MP3s are the classic trap. Variable bitrate files have no fixed relationship between position in the file and position in time, so reported durations can be wrong and seeks land off-target - a slice or a start-time offset in QLab may not hit where you set it. If a cue's waveform doesn't match what you hear, a VBR MP3 is the first suspect. Constant bitrate (CBR) fixes the length and seeking problems but not start timing: QLab's documentation says every MP3 has a variable, unpredictable decode delay when playback begins, so exact timing is impossible. Convert instead.
  • Encoder delay padding. MP3 and AAC add a short stretch of silence at the front of the file as a by-product of encoding, which matters the moment cues need tight timing against each other.

The habit that avoids all of it: treat compressed files as source material, and convert them to WAV before they go anywhere near the workspace.

Mono, stereo, and channel counts

Know what each file actually is before it hits your output patch. A mono file in a workspace patched for stereo pairs behaves differently to a stereo file, and a stereo file with identical channels is mono in disguise taking up two channels of routing. There's more on this trap in QLab workspace habits from real shows.
