REAPER Lua scripting for live recording

9 April 2026 · Updated 3 October 2026

REAPER exposes almost everything to scripts. Most of what you do in the UI is driven by actions, and most of those actions can be called from a script. If you record live shows or sessions and spend any time on prep, learning ten lines of Lua is one of the highest-return things you can do.

Why bother

Manual repetition is where you make mistakes. Renaming forty-eight inputs to match a stage patch, colouring each channel group, consolidating every track into a new take. Doing it by hand takes an hour and you will mistype some. A script takes the same hour to write the first time, then runs in a second forever after.

You don't need to be a programmer. You need to copy, paste, and read a function reference.

A real live-recording example: rename tracks from a CSV

This example uses Lua, the small scripting language REAPER exposes through ReaScript. The code below is one file you save and run from REAPER's Action List.

You turn up to a gig. The FOH engineer hands you their patch list as a CSV. Your REAPER session has forty-eight tracks called Track 1 through Track 48. You want them renamed in under a minute.

Save a file as patch.csv somewhere you'll find it again. One track per line, number then name:

1,Kick In
2,Kick Out
3,Snare Top
4,Snare Bottom
5,Hat
6,Tom 1
7,Tom 2
8,Floor Tom

Drop this script into ~/Library/Application Support/REAPER/Scripts/ and add it to the Action List:

local file = io.open("/Users/you/Desktop/patch.csv", "r")
if not file then return end

for line in file:lines() do
    local num, name = line:match("(%d+),(.-)\r?$")
    if num and name ~= "" then
        local track = reaper.GetTrack(0, tonumber(num) - 1)
        if track then
            reaper.GetSetMediaTrackInfo_String(
                track, "P_NAME", name, true)
        end
    end
end

file:close()
reaper.UpdateArrange()

The \r? at the end of the pattern matters. A CSV saved from Excel or on Windows ends each line with a carriage return before the line feed, and Lua on a Mac keeps it. Without the \r?, every track name carries an invisible character on the end.

Run the action, every track picks up the right name, ready to record. Change the CSV, run it again, names update. The same pattern works for colours, folder assignments, record-arm state, anything REAPER exposes on a track.

Going further

  • REAPER's built-in ReaScript documentation (Help > ReaScript documentation, which generates reascripthelp.html and opens it in your browser) lists every API function with its EEL2, Lua and Python prototype.
  • The SWS/S&M extension adds more actions you can drive from scripts.
  • Scripts live in a plain folder. Version them in git if you care about not losing them.

We've written a small set of these for common show-audio tasks. They're free, on the REAPER tools page. One of them, BSK Import: Track Names from CSV or Text, already does the job above: it reads a channel list exported from an Allen & Heath or Yamaha console editor, or a plain text file with one name per line, and renames or creates the tracks. Use them as-is, or copy the patterns and adapt them to your workflow.

Most of what a live recording engineer does before hitting record is deterministic, and anything deterministic can be a script. Don't try to automate everything, just stop doing the boring stuff by hand.
